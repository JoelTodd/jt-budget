# Curated optimisation guide

Do **not** merge `performance-optimisation-cycles` wholesale. Treat it as a research branch. The commit to `main` should contain **exactly the selected production optimisations below**, plus focused correctness tests and only the benchmark guardrails needed to prove these behaviours. Everything else should be discarded.

The app’s core contract must remain unchanged: it is a terminal-first monthly budgeting app that stores inspectable TOML files in a separate Git repository; confirmed guided steps and edited fields autosave; remote saves must use Git-backed sync; sync failures must block visibly; derived totals in TOML are inspection cache only and must be recomputed from editable state on load.  The optimisation log also warns that timings are local to the measured command and machine, so performance claims must be checked against the same scenario before being treated as evidence.

## Explicitly discard

Discard all optimisation cycles that are not needed to support the 20 items above. In particular:

* **Do not port rejected stale/no-reload shortcuts**: Cycle 17 cached month open, Cycle 18 no-reload rename/delete, Cycle 21 unconditional editor return, and Cycle 101 one-pass stale reconciliation. They either hide external file changes or regressed.
* **Do not port unsupported Git command experiments**: Cycle 24 plain `git add <path>`, Cycle 30/127 quiet push, Cycle 34 commit flags, Cycle 43 scoped mutation commits, Cycle 102 `git mv`/`git rm`, Cycle 129 quiet setup push, and Cycle 144 `pull --no-tags`. The current log repeatedly rejects these as neutral, noisy, slower, or semantically risky.
* **Do not weaken durability**: Cycle 25 and Cycle 106 show `no_temp_sync` is faster only by weakening the strict autosave durability boundary. Keep the existing durable atomic write semantics.
* **Do not add precomputed derived-cache write APIs**: Cycle 104 reverted this because the representative guided workflow regressed and the added API surface was not justified. Derived totals remain cache-only inspection data and must be recomputed on load.
* **Do not port broad lazy-loading designs**: Cycles 16 and 17 explain why changing what navigation state contains, or opening months from stale in-memory data, is a design change rather than a safe optimisation.
* **Do not port harness-only cleanup as part of the production commit** unless the destination branch already contains those harnesses and the cleanup is needed to keep retained tests coherent. This includes most of Cycles 45-60, 63-64, 67, 73-83, 110-147. Those cycles may be useful later, but they are not part of the curated production optimisation set.
* **Do not port total-only or superseded diagnostics** that later cycles removed, for example guided full harnesses, direct-path remote autosave/gate/open-list harnesses, direct-path remote failure/retry harnesses, old list-ordering comparisons, and fixture-strategy diagnostics. The later log standardises on production-shaped breakdowns and git-daemon remote evidence where remote behaviour matters.

## Required tests to bring over or recreate

The commit is incomplete unless these behaviours are covered by focused tests. Prefer small deterministic tests over broad ignored perf harnesses.

| Area                           | Required coverage                                                                                                                                                                            |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No-op saves                    | Unchanged editor commit creates no Git commit, leaves clean/synced state, and exits editing. Unchanged guided step advances without saving or committing.                                    |
| Existing-month autosave        | Tracked file uses the `commit --only` fast path. Existing untracked month falls back to staging and is committed. New month still stages safely.                                             |
| Local guided creation          | Draft file exists immediately. No Git commit is made during changed local-only guided steps. Completion creates exactly one month update commit and leaves the worktree clean.               |
| Remote editor pending sync     | Local commit happens first. UI route can render `Sync: pending`. Failed push routes to `BlockingFailure`. Retry pushes only the existing commit.                                             |
| Remote guided pending sync     | Initial draft and changed steps local-commit first. No-op/default steps do not save. Push failure blocks. Retry is push-only. Final transition preserves pending/synced messaging correctly. |
| Remote navigation pending sync | Fresh and stale rename/delete commit locally, update/reload/reconcile navigation as appropriate, enter pending sync, and block on push failure. Retry does not create another local commit.  |
| Repository gate                | Startup and explicit refresh render `RepositoryGate` before repository open/pull. Normal navigation is impossible until the gate succeeds. Pull/open failure goes to `BlockingFailure`.      |
| Startup validation             | Local-only repos open. Budget-shaped non-Git folders are rejected. Missing upstream on startup still blocks through pull failure. Setup/connect upstream validation still works.             |
| Editor return cache            | Cache restore only when metadata fingerprint matches. External month-file change forces reload. Autosave updates only the selected cached entry and invalidates if any other month changes.  |
| Navigation mutation freshness  | Fresh rename/delete updates in-memory list/fingerprint. Stale rename/delete reconciliation preserves unrelated external changes and produces a repository-matching fingerprint.              |
| Large-history listing          | Parallel loading triggers only at the large-history threshold. Ordinary 120-month listing remains sequential. Final ordering is deterministic.                                               |
| Create carry-forward           | Fresh cached previous month is reused. Target-exists, newer-prior, edited-prior, and missing-fingerprint cases fall back to disk.                                                            |
| TUI layout                     | Editor, navigation, guided creation, repository gate, and blocking failure render correctly at 80x24, 105x48, and 210x48.                                                                    |

## Strict done condition

This should not be treated as done when it compiles. It is done only when all of the following are true.

1. **Diff scope is exact**: the production diff contains only the 20 selected optimisations above and necessary supporting refactors. A reviewer can map every production change to at least one of these cycles: 1, 2, 5-7, 11-12, 14, 22-23, 26, 28-29, 31-33, 38-40, 42, 89, 91, or 100.

2. **No rejected candidate remains**: repository search must find no production references to rejected candidate concepts such as unconditional no-reload navigation restore, stale open-from-navigation reuse, `sync_data` durability swap, no-temp-sync writes, precomputed derived-cache write APIs, `git mv`/`git rm` mutation paths, `git push --quiet`, setup quiet push, or `pull --no-tags`.

3. **Behavioural test gate passes**:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build --release
```

These are the project’s published verification commands.

4. **Focused exact tests pass**: run the targeted tests for no-op commits, tracked/untracked save fallback, local guided one-commit completion, editor/guided/navigation pending sync failure and retry, repository gate, startup missing-upstream and non-Git rejection, editor return cache, stale navigation reconciliation, and create carry-forward fallback.

5. **Performance comparison is same-scenario**: run retained exact performance harnesses on the curated commit and, where possible, on `performance-optimisation-cycles` in the same machine/session. For first-feedback paths, the curated commit must be no worse than the branch by more than **10% or 2 ms**, whichever is larger. For remote sync totals, the curated commit must not move the sync boundary into first feedback and must not materially regress push/pull timing without a written explanation.

6. **Pending-sync semantics are visually proven**: run a local PTY smoke and a git-daemon remote PTY smoke. The remote smoke must visibly show `Sync: pending` before `synced` for at least editor autosave and guided creation, and must verify local `main` matches remote `refs/heads/main` after sync. Previous PTY smokes in Cycles 113-117 used this style of evidence and caught both valid flow and blocking-failure behaviour.

7. **Git invariants hold**: every path passed to Git is passed as an argument, with `--` where relevant. Errors include captured stdout/stderr. Success output is not parsed as logic. Retry paths must not create duplicate commits.

8. **File invariants hold**: all month writes remain atomic and durable. TOML remains inspectable. Derived totals are recomputed from editable state on load. No optimisation may trust persisted derived cache as source of truth.

9. **Cache invariants hold**: every cache has an explicit freshness proof and a full-reload fallback. A cache without a metadata/fingerprint check is not acceptable.

10. **Final manual audit is clean**: `git status` is clean after tests and smokes. The final commit message states that this is a curated high-impact optimisation port, not a merge of the optimisation branch.

A suitable commit message:

```text
Port high-impact performance optimisations

Keep strict TOML/Git persistence semantics while reducing avoidable Git work,
large-history reloads, and remote first-feedback latency. Exclude rejected
experiments, harness-only cleanup, and stale benchmark scaffolding.
```

## Rust and maintainability reminders

Keep the implementation deliberately plain. Use small helpers with clear names, explicit `Result` propagation, deterministic sorting after parallel work, and route-state transitions that are easy to inspect. Avoid `unsafe`, global mutable caches, background sync, broad state-machine shortcuts, and clever Git wrappers that obscure the failure boundary.

For concurrency, use scoped threads or an existing lightweight dependency only for independent month-file loading above the threshold. Do not share mutable route state across workers. Collect, validate, sort, then expose state to the UI.

For TUI code, preserve layout snapshots and supported sizes. Optimise row construction and visible slices, not user-visible layout semantics.

For Git code, keep command shapes explicit and tested. Remote failure must remain obvious and blocking. The pending-sync pattern is a visible strict boundary, not a background task.
